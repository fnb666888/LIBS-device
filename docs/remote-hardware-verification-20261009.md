## 发现并修复的问题

1. **采到首帧后误停机。** 真机 B2 在受控出光时报告 Q 光闸打开，原运行期门禁复查沿用出光前“光闸必须关闭”的判据，触发 `gate_lost_mid_run: q_gate_open`。现在由测量作业明确选择出光前/出光中检查阶段，出光前仍要求关闭光闸；运行中仍检查联锁、急停、故障、过温、设备可用及参数状态。保持真实 B2 读数，不篡改事实。
2. **正常停止被记成采集错误。** SDK 配合停止返回 `capture_cancelled` 时，作业先把它写为错误。现在仅在本作业已经请求停止时将其视作正常取消，保留此前的真实错误；不掩盖未请求停止时的异常取消。
3. **状态灯始终未装配。** 预检服务在设备打开之前绑定了空灯指针。现在等待设备打开后装配服务。
4. **K50 灯色下发失败。** 业务提供六路完整意图，但设备型号不支持逐路熄灭及蓝/白通道。驱动现在先全灭，再点亮支持的目标颜色，写前校验整份意图，避免残留旧灯色和不支持的指令；读回所有支持通道后才报告应用成功。
5. **守护进程退出访问已释放设备。** `Runtime::stop()` 关闭设备后，仍保留持有原激光器指针的测量作业；再次 stop 或析构时二次收光导致访问异常。现在停止并销毁设备消费者，再释放设备，支持重复停止及重新启动。

修复集中在主分支业务判定、驱动适配和生命周期，保留原架构及模型数学。

## 状态灯依据及验证

读取了项目中的 [厂家说明书](<../device-references/serial-devices/usb和485设备连接使用说明 (3)(1)/使用文档 .pdf>)（第 3、4 页）及 [科隆威通讯协议 v2.19](<../device-references/serial-devices/usb和485设备连接使用说明 (3)(1)/科隆威3色灯通讯协议v2.19.xlsx>)（Sheet1，I9:T20、I71:T105）。

通用 PDF 示例对应普通型号；协议表 T 列才是 K50 映射。结合旧分支协议实现及远端 2026-09-24 `lamp-20260924/10-demo-off.json` 至 `15-demo-off.json` 实际写入、查询记录，验证目录明确配置 `indicator_model: "CL50S+K50-485"`。

| --- | --- |
| 全灭 | `01 05 00 00 00 00 CD CA` |
| 红灯亮 | `01 05 00 01 FF 00 DD FA` |
